How It All Works Together
Here's what happens end-to-end when an LLM calls attach_ue(imsi="001010123456789", imei="imei-123456789"):



Step 1: LLM Client sends an MCP tool call over Streamable HTTP to :8010/mcp
Step 2: mcp_server.py receives it and calls the attach_ue() function
Step 3: attach_ue() uses the A2AClient to:
        a) Get a JWT token from Auth Service (:9000) — POST /auth/login
        b) Find the "orchestrate" skill in the Registry (:9001) — GET /registry/find/orchestrate
        c) Send a JSON-RPC call to the Supervisor (:8000) — POST /task with method "authenticate_subscriber"
Step 4: The Supervisor receives the task and autonomously:
        a) Finds the "auth" skill in Registry → discovers AUSF Agent (:8001)
        b) Calls AUSF /authenticate with the IMSI
Step 5: AUSF autonomously:
        a) Finds "auth-vectors" skill → discovers UDM Agent (:8003)
        b) Calls UDM /auth-vectors → gets RAND, AUTN, XRES crypto vectors
        c) Finds "trust" skill → discovers Security Agent (:8005)
        d) Calls Security /trust-score → gets trust score & risk level
        e) If trust < 0.7: triggers low-trust recovery
           → calls UDM /reverify-subscriber for fresh credentials
           → calls Security /re-evaluate-trust to elevate score
        f) Creates a session JWT token
        g) Returns: authenticated=true, session_token, trustScore, riskLevel, vectors
Step 6: Supervisor receives the AUSF result and:
        a) Finds "session" skill → discovers Subscriber Agent (:8002)
        b) Calls Subscriber /update-session to persist the session
        c) Returns the aggregated result to mcp_server.py
Step 7: mcp_server.py also calls Subscriber via "qos" skill for QoS data
Step 8: mcp_server.py assembles a clean response (stripping internal details):
        {
          "success": true,
          "authenticated": true,
          "trust_score": 91,
          "risk_level": "LOW",
          "session_token": "eyJ...",
          "qos_class": "QCI_1_URLLC",
          "service_plan": "6G_ROBOTICS_SLICE"
        }
Step 9: This JSON is returned to the LLM over MCP Streamable HTTP
The critical design: the MCP gateway only talks to the Supervisor for orchestrated workflows. The Supervisor discovers AUSF, UDM, Security, and Subscriber through the Registry on its own. The MCP gateway never manually coordinates those downstream agents — that's the Supervisor's job.

For messaging tools (send_ue_message, broadcast_ue_message, get_ue_inbox), the gateway looks up the UE agent's URL from the Registry and calls its REST endpoints directly, since peer messaging is a UE-level concern, not a Supervisor workflow.
